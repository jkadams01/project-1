# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A from-scratch, browser-based remake of Pokémon Platinum. Two deliberate design changes from the original:
- **All 1,025 species (Gens 1–9)** plus selected regional/alternate forms are obtainable.
- **No HMs.** Field traversal (cut/smash/strength/surf/waterfall/climb) is gated by a **key item + Gym badge** combination, never by teaching a Pokémon an HM move.

Pure vanilla JavaScript (ES5-style, no build step, no framework, no npm). Loads via classic `<script>` tags and runs over both `http://` and `file://`. All art (overworld tiles, trainer sprites, UI) is generated procedurally at runtime; only Pokémon battle sprites are fetched from the public PokeAPI sprite CDN, with a procedural fallback so the game is fully playable offline.

## Running and developing

```powershell
# Dev server (no-cache headers so edits always reload). Serves repo root at http://localhost:8741
py -3 tools/serve.py 8741
```

There is no build, lint, or test suite. "Tests" are done by driving the live game in a browser. The game exposes its scene stack and globals on `window.PKM`, and the engine's update loop can be stepped manually — inject a headless driver via the browser console / `preview_eval` to advance frames deterministically without `requestAnimationFrame`:

```js
// stepping the loop directly avoids real-time waits and rAF flakiness
function drive(frames){ for (var i=0;i<frames;i++){ PKM.Input.update(1/60); PKM.Scenes.update(1/60); } }
// synthesize input with real KeyboardEvents (PKM.Input listens on window)
function tap(code){ window.dispatchEvent(new KeyboardEvent('keydown',{code,bubbles:true})); drive(3);
                    window.dispatchEvent(new KeyboardEvent('keyup',{code,bubbles:true})); drive(2); }
// PKM.Overworld.state, PKM.Overworld.player, PKM.Scenes.stack, PKM.G (save state) are all readable
```

Key controls: arrows/WASD move, Z confirm, X cancel/run, Enter menu, M mute, `` ` `` turbo (`PKM.fastMode`).

## Data pipeline (generated files — DO NOT hand-edit)

Game data lives in `js/data/*.js`, but most of it is **generated by Python scripts in `tools/`**. Editing the generated `.js` directly will be silently overwritten on the next regen. Edit the generator instead, then rerun it.

| Generated file(s) | Generator | Source |
|---|---|---|
| `species.js`, `moves.js`, `learnsets.js`, `evolutions.js`, `expcurves.js`, `abilitynames.js` | `tools/build_data.py` | PokeAPI CSV dump in `tools/cache/` (gitignored) |
| `encounters.js` + `maps/hall_of_legends.js` | `tools/gen_encounters.py` | reads `species.js`/`evolutions.js` |
| `trainers.js` + `tools/trainer_manifest.json` | `tools/gen_trainers.py` | reads `species.js` |
| `maps/<town>_center.js`, `maps/<town>_mart.js` (all 15 towns) | `tools/gen_towns.py` | inline table |
| `<script>` list inside `index.html` (between `MAPS-START`/`MAPS-END`) | `tools/gen_index.py` | `js/data/maps/*.js` |

```powershell
# Full regen (build_data first — others read its output). Run gen_index after adding ANY map file.
py -3 tools/build_data.py        # needs tools/cache/*.csv (re-download from PokeAPI if missing)
py -3 tools/gen_encounters.py
py -3 tools/gen_trainers.py
py -3 tools/gen_towns.py
py -3 tools/gen_index.py
```

`build_data.py` requires the CSV cache. If `tools/cache/` is empty, re-download the named CSVs from
`https://raw.githubusercontent.com/PokeAPI/pokeapi/master/data/v2/csv/<name>.csv` (file list is at the top of `build_data.py`). Generators use a fixed RNG seed so output is deterministic.

**Hand-authored data** (safe to edit directly): everything else in `js/data/` and `js/data/maps/` — `typechart.js`, `items.js`, `dialogue.js`, `story.js`, and all the non-generated maps (towns proper, routes, dungeons, interiors).

## Architecture

Everything hangs off a single global, `window.PKM` (defined in `js/namespace.js`). There is no module system.

**Data registry.** Data files call `PKM.registerData(key, payload)`; maps call `PKM.registerMap(id, def)`; story scripts call `PKM.registerScripts({...})`. After all scripts load, `js/main.js` calls `PKM.initData()` to build lookup indexes (`speciesById`, `movesById`, `dexOrder`, …). Accessors: `PKM.species(id)`, `PKM.move(idOrIdent)`, `PKM.learnset(id)`, `PKM.typeMult(atk, defTypes)`, `PKM.expForLevel(growth, lvl)`.

**Script load order matters** (see `index.html`): `namespace` → `util` → data payloads → maps → engine modules → `story.js` → `main.js`. `story.js` loads *after* the engine because its scripts reference `PKM.State`, `PKM.Dialog`, etc. at definition time. `main.js` is always last.

**Scene stack** (`PKM.Scenes` in `main.js`). The whole game is a stack of scenes, each `{update(dt), draw(ctx), overlay?}`. Only the top scene updates; drawing starts from the lowest non-overlay scene upward (so dialog/menus render over the overworld). The main loop is `Input.update → Scenes.update → Scenes.draw` per rAF frame. Scenes: `Title`/`Intro`/`StarterScene` (`title.js`), `Overworld` (singleton), `Battle` + `EvolutionScene` (`battle.js`), and the menu/dialog overlays.

**Engine vs. data split.** `js/engine/*` is logic; `js/data/*` is content. The engine knows nothing about specific Pokémon, maps, or story beats — it reads them from the registry.

**Pokémon instances are plain JSON-serializable objects** (no classes), created by `PKM.Mon.make(pokeId, level, opts)`. This is what makes save/load trivial — `PKM.Save` just `JSON.stringify`s `PKM.G` (the entire game state: party, boxes, bag, flags, dex, position) into `localStorage`. `PKM.Mon` holds all the stat/exp/evolution math as free functions over these objects.

**Global game state** is `PKM.G` (shape defined in `state.js` `newGame()`). `PKM.State` is the mutation API over it: `flag`/`setFlag`, bag ops, `givePokemon`, `markSeen`/`markCaught`, `healParty`, and crucially `canUseField(what)` / `fieldHint(what)` which encode the **no-HM gating** (key item + badge → traversal).

**Story scripting.** `PKM.SCRIPTS[id] = function(done, ctx){ ... }`. Scripts run via `PKM.Events.run(id)`, which **locks the overworld** (`ow.locked`) until `done()` is called — so every async chain (dialog → battle → movement) MUST eventually call `done`, or the player is frozen. Scripts are triggered by map `triggers`, NPC `script` fields, and tile interactions. `PKM.Events` also has helpers: `giveItem`, `giveMon`, `moveNpc(npc, path, done)`, `engageTrainer`, `trainerSpotted`.

**NPC scripted movement is driven by the overworld update loop, not timers.** `moveNpc` sets `npc.path` (a string like `'uull'`, `'w'` = pause) and `npc.pathDone`; `overworld.js`'s update consumes one step per arrival. This is intentional so cutscenes work under headless frame-stepping — do **not** reintroduce `setInterval`/`setTimeout`-based movement.

### Map definition format

A map is `{ name, theme, music, tiles: [strings], warps, connections, npcs, triggers, signs, items, encounters, ... }`. `tiles` is an ASCII grid; each character is both collision and a procedural tile drawn by `gfx.js`. The character vocabulary is defined in `js/engine/gfx.js` (`drawTileInto`) and collision in `js/engine/overworld.js` (`WALKABLE`, `canEnter`). Notable chars:

- Walkable: `.` ground, `,` tall grass (wild encounters), `=` path, `*` flowers, `D` door/warp, `-` bridge, `s` shallow water, `i` ice.
- Blocking: `#` themed block (tree/wall/rock per theme), `S` sign.
- **Field-move obstacles** (cleared via key-item+badge, the no-HM system): `T` cuttable tree, `R` smashable rock, `B` strength boulder, `C` climbable wall, `~` deep water (surf), `W` waterfall, `^` ledge (one-way jump down).

`theme` selects a tile atlas/palette (`outdoor`, `forest`, `cave`, `snow`, `gym`, `galactic`, `distortion`, `center`, `mart`, …; full list in `gfx.js` `THEMES`). `connections` join map edges seamlessly; `warps` are point-to-point teleports. Encounter tables are keyed by `encounters` (a string id into `encounters.js`) with `grass`/`water`/`fishing` slots; each row is `[pokeId, minLvl, maxLvl, weight]`.

### Battle system

`js/engine/battle.js` is the largest/most complex file: full damage formula, the 18-type chart (`typechart.js`), stat stages, status conditions, weather, ~40 abilities, multi-hit/2-turn/recharge moves, hazards, screens, trainer AI, and the capture formula. Move *effects* are data-driven from the PokeAPI `meta` fields baked into `moves.js` (ailment, category, stat changes, drain/heal, flinch, crit) plus a set of named-move override tables at the top of the file for mechanics the metadata can't express. Battles are a queue of animation/message/function steps processed in `update`.

### Coverage guarantee (the "all 1,025" requirement)

`gen_encounters.py` enforces that every non-legendary species reachable only from the wild is placed in some encounter table (distributed by base-stat-total and biome), evolution-only species are excluded from the must-place pool, and every legendary/mythical gets a static encounter pedestal in the generated `hall_of_legends` map. When changing encounter logic, preserve this invariant.
